# Проверка Telegram Sandbox

Проверено 11 ноября 2026 года в Windows, Python 3.12.10.

## Выполненные проверки

- `uv run pytest -q`: **38 passed**, 3.27 секунды в заключительном запуске.
- `uv run ruff check .`: **All checks passed**.
- `uv run ruff format --check .`: форматирование проверено.
- `uv build`: собираются исходный архив и wheel `telegram_sandbox-0.1.0`.
- `uv run python -m sandbox_bot --help`: точка запуска доступна.
- Отдельный процесс приложения в режиме `--api-only`: настоящий HTTP-запрос к
  localhost, чтение статуса, команды через stdin, проверка результата через API,
  завершение по `quit` с кодом 0. Данные теста создаются во временной папке.

## Что покрывают тесты

1. Сохранение и изоляция профилей/материалов между чатами, в том числе после переоткрытия SQLite.
2. Безопасные значения по умолчанию: online, чат выключен, интернет выключен.
3. Фильтрация выключенных чатов, online, групп, ботов, исходящих сообщений и Избранного.
4. Запрещённые сообщения не запускают ни скачивание вложения, ни вызов модели.
5. В контексте ИИ нет материалов другого чата и предыдущего входящего сообщения.
6. Ответы/входящие не добавляются в материалы автоматически.
7. Изменение статуса, разрешения, материала и ручной ответ отменяют генерацию.
   Проверяется также online → busy в течение одной генерации и изменение во время загрузки файла.
8. Защита от повторной обработки, отсутствие повторной отправки после сетевой ошибки.
9. UTF-16 лимит ответа с эмодзи.
10. UTF-8 текст, DOCX, PDF с реальным текстовым слоем, отклонение пустого PDF.
11. Проверка и нормализация изображения, повреждённый файл, бинарный текст,
    неподдерживаемый формат и превышение размера.
12. Проверка размера/расширения Telegram-вложения до скачивания.
13. HTTP payload модели: multimodal, bearer, выбранная модель, `store: false`.
14. Инструмент поиска: разрешённый запрос выполняется, попытка передать факт
    песочницы, которого нет в текущем сообщении, блокируется кодом.
15. Ошибка провайдера не порождает повторный запрос и не раскрывает тело ответа.
16. Авторизация management API, включая OpenAPI, изменение статуса/профиля,
    загрузка материала и удаление только из указанной песочницы.
17. Проверка неизвестных полей, возраста, отрицательного ID и логических значений.
18. Отсутствие CORS, проверка авторизации до разбора multipart, лимит HTTP body.
19. Консольный сценарий управления; пути Windows с пробелами и обратными слешами.
20. Блокировка второй копии с той же папкой данных и освобождение lock после выхода.
21. В журнал не попадают тексты ошибок с содержимым файла и имитацией секретного API key.

## Проверка чувствительности теста

Временно инвертировано правило `status != "online"` в движке.
Тест для online завершился ошибкой assertion, как и должен.
Исходный движок восстановлен. При этой проверке обнаружен и исправлен недостаток
первоначального теста: тестовая ошибка скачивания перехватывалась кодом приложения.
Теперь тест явно проверяет факт отсутствия скачивания и вызова ИИ.

## Исправления, найденные при реализации и проверке

- Явно задан каталог Python-пакета для корректной сборки.
- Версии состояния предотвращают отправку ответа по устаревшим настройкам.
- ID сообщения резервируется до внешнего вызова, чтобы не дублировать ответ после сбоя.
- Telegram считает длину по UTF-16: обычное обрезание Python-строки заменено на корректное.
- Учтена секундная точность Telegram date при фильтрации событий запуска.
- Собственные автоответы отделены от ручных исходящих при отмене генерации.
- API проверяет токен и лимит body до обработки multipart.
- Имена загружаемых файлов не используются как пути записи.
- Поиск не может дописывать сведения из песочницы в свой запрос.
- Консольный ввод не блокирует event loop и штатное завершение по quit.
- В локальном runtime-тесте отключено влияние системного HTTP proxy.

## Что не проверено с живыми сервисами

Реквизиты пользователя не предоставлялись и не запрашивались в чате.
Поэтому **не выполнены** вход в настоящий аккаунт Telegram, отправка реальному
собеседнику, вызов выбранной внешней модели и настоящий поиск с ключом Tavily.
В этих границах используются тестовые объекты/httpx MockTransport.
Локальный HTTP-сервер, SQLite и разбор файлов проверяются реальными реализациями.

Совместимость конкретного провайдера с vision, function calling и `store: false`
нужно проверить после ввода реквизитов. Также не заявляются нагрузочное тестирование,
гарантированная защита от всех prompt injection, OCR или поддержка произвольных форматов.
Подробные эксплуатационные ограничения описаны в README.md.
