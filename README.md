# Sova — панель и Telegram Sandbox

В этом репозитории теперь есть полноценная веб-панель: React + TypeScript,
Cloudflare Pages Functions / Workers, вход владельца по случайному паролю, настройки
песочниц/ИИ, графики и кастомизация оформления.

**Публикация сайта:** [пошаговая инструкция Cloudflare](DEPLOYMENT.md).
**Новый простой вход:** [настройка пароля](PASSWORD_LOGIN.md). Нужен один дополнительный
секрет `OWNER_PASSWORD`; прежние настройки Access больше не нужны.
Build command: `npm run build`. Output directory: `web-dist`. Node: `22`.
Сайт и обновлённый Python-бот находятся в одном репозитории. Для локального просмотра
сайта: `npm ci` → `npm run dev` → «Посмотреть демопанель».

Автоответчик вашего **личного Telegram-аккаунта** с отдельной песочницей для каждого собеседника.
Управление из консоли, веб-панели и через HTTP API.

## Быстрый запуск в Windows

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Откройте PowerShell в этой папке:

```powershell
$env:PYTHONUTF8 = "1"
uv sync --locked
uv run --locked python -m sandbox_bot
```

Или запустите `start.cmd`. Скрипт переключается в папку проекта, устанавливает зависимости
из lock-файла и запускает приложение. Файлы данных создаются в `data/` этой папки.

При запуске последовательно вводятся:

1. Токен управления: свой, минимум 24 ASCII-символа без пробелов, или Enter для генерации.
   Сгенерированный токен показывается один раз; сохраните его для обращения к API.
2. Telegram API ID и API hash из [my.telegram.org/apps](https://my.telegram.org/apps).
3. Base URL ИИ, например `https://ваш-провайдер/v1`. Путь `/chat/completions` добавляется приложением.
4. API key ИИ и точное имя модели у вашего провайдера.
5. Необязательный API key [Tavily](https://www.tavily.com/) для интернет-поиска, либо Enter.
6. При первом входе — телефон, код Telegram и пароль 2FA, если включён.

API ID/hash сами по себе не авторизуют аккаунт: телефон/код/2FA нужны при создании сессии.
При следующих запусках используется локальная `data/telegram.session`, поэтому код обычно не нужен.
API hash, ключ ИИ и ключ поиска вводятся скрыто и приложением не записываются в настройки.
Для локальной модели без проверки ключа введите `local`. HTTP Base URL разрешён только
на localhost; для внешнего сервера требуется HTTPS.

**После каждого запуска статус сбрасывается в `online`: приложение молчит до вашего переключения.**
Песочницы и разрешения чатов сохраняются между запусками.

## Настройка чата

Команды вводятся в приглашении `sandbox>`, а не в PowerShell и не в Telegram.
Сначала выполните `dialogs`, найдите нужный личный чат и скопируйте его числовой ID.
В примере `123456789` замените на настоящий ID:

```text
dialogs
profile 123456789 name "Марк"
profile 123456789 age 25
profile 123456789 location "Москва"
note 123456789 "По рабочим вопросам я доступен после 19:00."
upload 123456789 "C:\Users\marko\Documents\about-me.pdf"
show 123456789
enable 123456789
status busy
```

Чат начнёт получать автоответы только после `enable` и при статусе, отличном от `online`.
Имя, возраст, местонахождение и материалы для другого ID задаются независимо.
Отсутствующее поле считается неизвестным. Удалить возраст: `profile ID age null`;
очистить имя или место: `profile ID name ""` / `profile ID location ""`.

| Команда | Действие |
| --- | --- |
| `status online` | Остановить автоответы во всех чатах |
| `status offline` | Владелец не в сети |
| `status busy` | Владелец занят |
| `status unavailable` | Владелец не может ответить |
| `enable ID` / `disable ID` | Разрешить / запретить ответы этому собеседнику |
| `chats` | Настроенные песочницы |
| `dialogs` | Личные диалоги Telegram: ID, название и разрешение |
| `show ID` | Профиль и ID загруженных материалов |
| `note ID "текст"` | Добавить информацию владельца |
| `upload ID "полный путь"` | Добавить файл в песочницу |
| `remove ID MATERIAL_ID` | Удалить материал из конкретной песочницы |
| `web ID on` / `web ID off` | Разрешить / запретить поиск для конкретного чата |
| `help` | Показать команды |
| `quit` | Завершить приложение |

Telegram-статус присутствия не используется для решения об ответе. Статус задаёте вы.
Никаких команд от собеседников для изменения песочниц приложение не принимает.
При ручном исходящем сообщении ожидающий ответ в этом чате отменяется; следующие
входящие снова могут получить ответ, пока вы не поставите `online` или `disable ID`.

## Что получает ИИ

Каждый запрос заново состоит из системного правила, ручного статуса, профиля и
всех материалов **одного текущего чата**, а также **одного текущего сообщения** с его
вложением. История, сообщения других чатов, цитируемые сообщения и предыдущие ответы
не подгружаются. У альбома каждое сообщение обрабатывается отдельно.

Входящие сообщения и ответы не сохраняются как память и не добавляются в песочницу.
Локально сохраняются профиль, материалы, разрешения, статус, версии изменений и пары
ID чата/сообщения для защиты от повторной обработки. Тексты переписки не логируются.
Название собеседника из списка `dialogs` не добавляется в контекст ИИ автоматически.

Не выбранные личные чаты, группы, каналы, боты и Избранное не получают автоответов.
Вложения запрещённых чатов не скачиваются. При смене статуса, настройке песочницы,
отключении чата или ручном ответе результат незавершённой генерации отбрасывается.
Если отправка уже ушла в Telegram, последующая смена статуса не может отозвать её.

**Изоляция ограничивает данные запроса, но не знания обученной модели.** Модель знает
общие сведения и может ошибиться или поддаться prompt injection. Инструкция запрещает
выдумывать факты о владельце, однако математической гарантии отсутствия разглашения
или выдумок у генеративной модели нет. Всё загруженное в конкретную песочницу следует
считать разрешённым для обработки в разговоре с этим собеседником.

Провайдер ИИ получает содержимое запросов, включая разрешённые материалы и изображения.
Запросы отправляются с `store: false`, но это не заменяет политику хранения провайдера.
Для работы нужны OpenAI-compatible **Chat Completions**, для изображений — vision-модель,
для поиска — поддержка function tools. API Responses/Anthropic/Gemini напрямую не подключены.

## Файлы и интернет

Поддерживаются входящие вложения и материалы владельца:

- TXT, MD, JSON, CSV, LOG, YAML в UTF-8;
- PDF с текстовым слоем, до 100 страниц; зашифрованные PDF отклоняются;
- DOCX: текст абзацев и таблиц;
- JPEG, PNG, WEBP, GIF: первый кадр, нормализация в JPEG и уменьшение до 1024×1024.

Лимит файла — 8 МБ, извлечённого текста — 100000 символов, изображения — 20 мегапикселей.
На всю песочницу — 200000 символов сериализованных материалов, включая base64 изображений.
Большое изображение может не поместиться: уменьшите его или удалите ненужные материалы.
Также учитывайте размер контекстного окна вашей модели: весь разрешённый контекст отправляется
целиком, автоматического обрезания или скрытого выбора документов нет.

Сканы PDF без текста требуют OCR, который не подключён. Видео, голосовые сообщения,
архивы, EXE, XLSX и другие форматы не анализируются. При неподдерживаемом или повреждённом
входящем файле автоответ пропускается, в консоли появляется тип ошибки без содержимого.
Бот не исполняет файлы и не скачивает произвольные ссылки из сообщений.

Интернет работает через инструмент Tavily: нужен ключ при запуске и `web ID on`.
Без обоих условий поиск недоступен. Модель сама решает, нужен ли поиск.
Поисковый запрос должен быть точной подстрокой текущего входящего сообщения длиной
2–300 символов: это проверяется кодом. Добавить в запрос личные данные из песочницы нельзя.
За один ответ допускается один раунд инструментов, до трёх запросов.
Результаты поиска возвращаются только в рамках текущего ответа и не становятся памятью.
Tavily получает выбранный фрагмент сообщения; поиск и ИИ могут тарифицироваться отдельно.

## API для будущего сайта

Адрес: `http://127.0.0.1:8765`. Все маршруты, включая схему OpenAPI, требуют заголовок:

```http
Authorization: Bearer YOUR_ADMIN_TOKEN
```

Токен можно задать переменной окружения `SANDBOX_ADMIN_TOKEN`, иначе он запрашивается
при запуске. Сервер привязан к localhost; CORS не включён.
Будущий сайт подключается через серверную часть/reverse proxy на том же хосте.
Для удалённого доступа потребуются HTTPS, собственная авторизация сайта и корректный proxy;
не помещайте административный токен в публичный JavaScript.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/v1/health` | Процесс работает, подключён ли Telegram |
| GET / PUT | `/api/v1/status` | Прочитать / изменить статус |
| GET | `/api/v1/dialogs` | Получить список личных диалогов из Telegram |
| GET | `/api/v1/chats` | Список настроенных песочниц |
| GET / PATCH | `/api/v1/chats/{id}` | Прочитать / изменить разрешение и профиль |
| GET / POST | `/api/v1/chats/{id}/materials` | Прочитать материалы / добавить заметку |
| POST | `/api/v1/chats/{id}/files` | Загрузить файл, multipart поле `file` |
| DELETE | `/api/v1/chats/{id}/materials/{material_id}` | Удалить материал |
| GET | `/openapi.json` | Схема API для разработки сайта |

Пример PowerShell:

```powershell
$headers = @{ Authorization = "Bearer ВАШ_ТОКЕН" }
Invoke-RestMethod http://127.0.0.1:8765/api/v1/status -Headers $headers
Invoke-RestMethod http://127.0.0.1:8765/api/v1/status -Method Put -Headers $headers `
  -ContentType "application/json" -Body '{"status":"busy"}'
Invoke-RestMethod http://127.0.0.1:8765/api/v1/chats/123456789 -Method Patch -Headers $headers `
  -ContentType "application/json" -Body '{"enabled":true,"web_enabled":false}'
```

`PATCH` принимает `enabled`, `name`, `age`, `location`, `web_enabled`.
Добавление заметки: `{"title":"Обо мне","text":"Разрешённая информация"}`.
Ответ на добавление заметки/файла: `{"id":1}`. Возраст очищается через `{"age":null}`.
Отрицательные ID, неизвестные поля и невалидные типы отклоняются кодом 422.
API позволяет подготовить песочницу по положительному ID до появления чата;
разрешение ID не делает группу или бота допустимым получателем.

Для разработки сайта без реквизитов Telegram/ИИ:

```powershell
uv run python -m sandbox_bot --api-only
```

В этом режиме доступны управление и консоль; `/dialogs` возвращает 503.
`--no-console` оставляет только HTTP API, `--port 9000` меняет порт,
`--data-dir "D:\bot-data"` выбирает папку сессии и базы.
Запускать несколько процессов с одной папкой данных нельзя: установлен файловый lock.

## Хранение и поведение при ошибках

`data/telegram.session` даёт доступ к аккаунту. База `data/state.sqlite3` содержит
разрешённые вами материалы. Они не зашифрованы приложением: ограничьте доступ к папке
средствами ОС. Эти файлы, ключи и локальные окружения исключены из Git.
Удаление материала убирает его из будущих запросов; SQLite/WAL и резервные копии
могут сохранять старые байты, это не инструмент гарантированного стирания.

При сетевой ошибке, ограничении Telegram, пустом ответе или ошибке провайдера приложение
пропускает автоответ. Повторной отправки нет: ID сообщения помечается до генерации.
Это предотвращает дубли при перезапуске, но означает, что аварийно прерванный ответ
не будет автоматически восстановлен. Старые сообщения до запуска не обрабатываются.
Ответ ограничивается 3500 UTF-16 единицами, форматирование Telegram отключено.

## Проверка

```powershell
uv sync --locked --extra dev
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv build
```

Тесты используют реальную SQLite, разбор PDF/DOCX/изображений, ASGI API и отдельный
процесс с настоящим HTTP-сервером и консолью. Внешние Telegram/AI/Tavily заменены
на тестовые сетевые границы. Подробности результатов — `VERIFICATION.md`.

После ввода реальных реквизитов проверьте на одном тестовом личном чате:
песочница A отличается от B; offline/busy/unavailable отвечают, online молчит;
файл/изображение распознаются выбранной моделью; выключенный чат не отвечает;
при включённом поиске модель получает свежий результат. Живую проверку следует
проводить с собеседником, которому разрешено видеть загруженные тестовые данные.

Источники интерфейсов: [Telethon — вход](https://docs.telethon.dev/en/stable/basic/signing-in.html),
[Telethon — события](https://docs.telethon.dev/en/stable/modules/events.html),
[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create),
[Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search).
