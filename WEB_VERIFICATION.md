# Проверка веб-панели Sova

Обновление: вход Cloudflare Access заменён паролем. Актуальные проверки нового входа
описаны в PASSWORD_LOGIN.md и tests-web/security.test.ts: 42 Python-теста, 19 веб-тестов,
6 браузерных сценариев, cookie-сессии, серверный отзыв,
смена пароля, общий лимит попыток в SQLite, fail-closed при отключённом боте.
Ниже сохранён отчёт о первоначальной версии, проверки JWT относятся к прежнему входу.

11 ноября 2026. Windows, Node 22.23.2, Python 3.12.10, Chromium через Playwright.

- **40 Python-тестов:** исходные ограничения бота, изоляция данных, гонки, файлы,
  авторизация API, новые метрики и смена ИИ. Ключи не возвращаются и не пишутся в SQLite.
- **15 Vitest-тестов:** настоящая подпись RS256 и проверка owner JWT, другой email,
  неверный audience, истёкший/испорченный токен, поддельный email-header, CSRF,
  allowlist proxy, отсутствие пересылки cookies и пользовательских ключей,
  блокирование редиректов и секретных тел ошибок. Демо не вызывает fetch к API бота.
- **5 Playwright-сценариев:** все разделы, управление статусом, профиль/заметки,
  отсутствие заметки в другой песочнице, смена модели, сохранение черновика при
  обновлении, мобильный экран, тема/акцент, клавиатура, состояние недоступного backend.
- **axe-core:** автоматические проверки WCAG 2 A/AA и 2.1 AA на всех основных
  светлых экранах, редакторе песочницы и мобильном тёмном обзоре — без нарушений
  в проверенных состояниях. Это не заменяет полный ручной аудит доступности.
- TypeScript strict + noUnusedLocals, Vite production build, Prettier, Ruff — проходят.
- npm audit: **0 уязвимостей** на момент проверки.
- Wrangler успешно компилирует Cloudflare Function. В локальном Cloudflare runtime
  проверены заголовок CSP статической страницы и 503 fail-closed API без конфигурации.
- Скриншоты desktop/mobile просмотрены. Нет горизонтального переполнения при
  320, 390 и 1440 px в проверенных сценариях; нет необработанных JS-ошибок.

Найдено и исправлено: базовые цвета тёмной темы, контраст подписей и badges,
фокус скрытой мобильной навигации, сброс черновика модели при автообновлении,
потеря загруженной истории журнала при обновлении, недоступность ручного добавления
ID при ошибке списка диалогов. Смена хоста ИИ требует новый ключ, чтобы исключить
случайную передачу прежнего ключа другому провайдеру.

Сборщик Vite предупреждает о React Server Components-директиве `use client`
в lucide-react. Здесь обычное клиентское SPA, Server Components не используются;
предупреждение не влияет на сборку и поведение. Сам браузер не имеет необработанных
ошибок приложения; ожидаемые 401/503 при отсутствии настройки отображаются в интерфейсе.

Не проверено: production deployment в аккаунте Cloudflare пользователя, настоящий
вход через его Access policy, живой Telegram, выбранный ИИ и Tavily. Секреты и домен
пользователя не вводились. Точная последовательность настройки описана в DEPLOYMENT.md.
GitHub Actions настроены в репозитории; их удалённый результат нужно отличать от
перечисленных выше локальных проверок.
