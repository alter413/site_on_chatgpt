# Telegram Sandbox

Цель: автоответчик личного аккаунта Telegram с изолированным контекстом каждого чата.
Новое поручение владельца: ввод API ID/hash, телефона, кода Telegram, 2FA и параметров
ИИ на сайте. Веб-режим --web сохраняет реквизиты и StringSession в Fernet-хранилище,
восстанавливает их при запуске и не записывает коды/2FA. Начальная связка Worker/API
через служебный токен остаётся необходимой. Самостоятельная публикация статической
папки не должна выдавать себя за работающее серверное приложение.
Уточнение владельца: простой вход без Cloudflare Access, криптографически случайный
пароль 256 бит. Сессии на 8 часов и лимит 10 попыток/15 минут хранятся в SQLite бота;
для входа не требуется дополнительное облачное хранилище. Пароль выдаётся локальным
файлом и никогда не включается в Git или сборку сайта.
Дополнение 11.11.2026: по поручению пользователя добавляется сайт в репозиторий
alter413/site_on_chatgpt с Cloudflare Pages, owner-only Access, настройками ИИ,
реальными метриками, кастомизацией и адаптивным интерфейсом. Пользователь разрешил
дополнительные полезные функции и публикацию кода в этот репозиторий.
Пользователь уже поручил реализацию и проверку; дополнительные продуктовые функции
согласовываются отдельно, реализация перечисленных требований продолжается без пауз.

Модули и порядок: storage → attachments → engine → telegram; storage → management API/CLI.
Python 3.12, Telethon 1.x, SQLite, FastAPI, OpenAI-compatible Chat Completions через httpx.

Критерии:
- API ID/hash, AI URL/key/model вводятся при запуске; секреты не печатаются и не сохраняются.
- Вход по телефону/коду/2FA, локальная session. Не BotFather.
- Личные чаты выключены по умолчанию; группы, каналы, боты и Избранное игнорируются.
- Ручной глобальный статус online/offline/busy/unavailable. Online запрещает автоответ.
- Профиль name/age/location и загруженные владельцем материалы отдельны для каждого chat_id.
- В запросе только текущая песочница и текущее сообщение/вложение, без истории и reply-цепочек.
- Входящие сообщения никогда автоматически не пополняют песочницу.
- Изменение статуса/песочницы или ручной ответ во время генерации отменяет устаревший ответ.
- Поддержка текста, изображений, TXT/MD/JSON/CSV/PDF/DOCX. Другие форматы явно отклоняются.
- Интернет: опциональный инструмент поиска Tavily, отдельно разрешённый для каждого чата.
- API /api/v1 с bearer-токеном, localhost, без CORS по умолчанию; OpenAPI для будущего сайта.
- Консоль: список чатов, включение/выключение, статус, профиль, заметки, файлы, просмотр/удаление.
- Сетевые ошибки не порождают автоматических повторных отправок; содержимое сообщений не логируется.

Структура: sandbox_bot/ — приложение, tests/ — тесты поведения, README.md — запуск и ограничения.
Команды: `uv sync --extra dev`; `uv run pytest -q`; `uv run ruff check .`;
`uv run python -m sandbox_bot`; `uv run python -m sandbox_bot --api-only`.
Стиль: явные типы и короткие функции, например `def set_status(status: Status) -> None`.
Всегда: проверять границы контекста, аутентификацию API, гонки и реальные форматы вложений.
Сначала спросить: новые продуктовые функции. Никогда: коммитить секреты/сессии или читать историю для ИИ.
Тесты: SQLite и HTTP API реальные; Telegram/AI заменяются только на внешних сетевых границах.
Без реквизитов владельца живая авторизация и ответы внешней модели остаются непроверенными.
