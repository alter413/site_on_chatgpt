# Настройка Telegram и ИИ с сайта

Запустите **`start-web.cmd`** на машине бота. Телефон, Telegram API ID/hash,
код и параметры ИИ теперь вводятся в панели сайта. Дополнительный облачный сервер
для хранения реквизитов не требуется: их хранит постоянно работающее Python-приложение.

## Первый запуск

1. Обновите файлы бота, сохранив прежнюю папку `data/`. Запустите `start-web.cmd`.
2. Только при первом запуске задайте или сгенерируйте служебный токен API. Укажите
   его в `BOT_ADMIN_TOKEN` Worker, а HTTPS-адрес Tunnel — в `BOT_API_URL`.
   В режиме `--web` этот токен запоминается зашифрованным и повторно не запрашивается.
3. Установите новый полный Worker и войдите паролем владельца.
4. В разделе **«Подключение»** укажите **Telegram API ID**, **API hash** и **телефон**.
   Нажмите **«Получить код Telegram»**.
5. Введите код. Telegram сам выбирает способ доставки, обычно код приходит
   в приложение на другом устройстве. Если включена 2FA, появится отдельное поле пароля.
6. После подключения откройте **«Модели и ИИ»**: укажите **Base URL**, **API key**,
   **модель** и при необходимости ключ Tavily. Сохраните настройки.

Далее бот сам восстанавливает настройки и сессию из той же `data/` при запуске.
Статус после запуска и подключения остаётся **«Онлайн»**. Автоответы начнутся,
когда владелец разрешит нужные чаты и вручную изменит статус.

Команда для запуска вручную:

```powershell
uv sync --locked
uv run python -m sandbox_bot --web --data-dir "C:\путь\к\data"
```

`--no-console` оставляет управление только с сайта. `SANDBOX_ADMIN_TOKEN` в окружении
можно использовать для явной замены служебного токена; после замены обновите и секрет Worker.
Старый режим консольного входа без `--web` остаётся доступен.

## Хранение

- `data/config.enc`: зашифрованные API ID/hash, телефон, ключи ИИ, служебный токен
  и сессия Telegram. Используется Fernet из cryptography с проверкой целостности.
- `data/vault.key`: автоматически созданный ключ. На POSIX создаётся с режимом 0600.
  В Windows доступ к папке нужно ограничить средствами ОС. Можно вместо файла задать
  ключ в переменной окружения **SOVA_VAULT_KEY** (Fernet key).
- Код Telegram, phone_code_hash и пароль 2FA в файл настроек не записываются.
  Код и 2FA действуют только в рамках текущей попытки входа в памяти процесса.
- Новая веб-сессия Telegram сохраняется внутри зашифрованного хранилища, без создания
  новой plaintext `.session` базы. Прежний `telegram.session` может быть импортирован;
  существующий файл при импорте автоматически не удаляется ради совместимости.
- В API возвращаются номер телефона для удобного редактирования владельцем, статус,
  API ID и признаки сохранения ключей. API hash, ключи, содержимое сессии и 2FA
  обратно в браузер не возвращаются.

Сохраните резервную копию `config.enc` и ключа отдельно от публичных файлов сайта.
Кто получил и зашифрованный файл, и ключ, сможет прочитать данные. Шифрование не
защищает от полного доступа к компьютеру бота. При потере или повреждении ключа
приложение сообщает ошибку и не перезаписывает хранилище.

## Повторный вход и выход

Сохранённая действующая сессия восстанавливается без повторного кода. Если Telegram
её отозвал, в панели потребуется запросить код снова. Незавершённая попытка входа
после перезапуска не восстанавливается: приложение не отправляет новый код автоматически.

Неверные коды/2FA ограничены пятью попытками, повторный запрос кода — не чаще минуты.
FloodWait Telegram отображается безопасным сообщением. Неизвестные ответы SDK,
ключи и коды не выводятся в журнал или ошибки сайта.

Кнопка **«Выйти из Telegram»** требует подтверждения и отзывает эту сессию.
Песочницы сохраняются, статус переключается в «Онлайн».

## Если форма входа на сайт не работает

Загрузка папки в окно **Upload your static files** публикует интерфейс без API.
Для рабочего входа и настройки аккаунта нужен полный Worker через **Edit code**
или публикация из Git с серверной частью. Новая форма явно показывает 404/405
серверного входа и ошибку неполного пароля, вместо незаметной блокировки браузером.

## Проверка без реальных реквизитов

В демопанели откройте «Подключение», выйдите из демонстрационного аккаунта и пройдите
мастер: код **12345**, любой непустой пароль 2FA. Демо не обращается к Telegram.

Автотесты используют тестовую границу Telegram; SQLite, шифрование, HTTP API,
восстановление StringSession и интерфейс проверяются реальными реализациями.
Вход в настоящий аккаунт требует реквизитов владельца и отдельно не заявляется проверенным.
