# Вход в Sova по одному паролю

Вход владельца теперь работает по случайному секретному паролю без Cloudflare Access,
почты и одноразовых писем. Сайт по-прежнему закрывает API до авторизации.

## Настройка

1. Обновите Python-бот из этого репозитория. Сохраните и используйте прежнюю `data/`:
   песочницы останутся, новые таблицы сессий и попыток создадутся автоматически.
2. Установите новый полный Worker-файл через **Edit code → Deploy**. Для Pages с Git
   используйте обычный новый deployment из main.
3. В **Settings → Variables and Secrets** добавьте **Secret `OWNER_PASSWORD`**.
   Используйте сгенерированный случайный пароль из 43 URL-safe символов (256 бит).
4. Два прежних параметра подключения остаются: `BOT_API_URL` — HTTPS-адрес Tunnel;
   `BOT_ADMIN_TOKEN` — секретный токен того же Python-бота.
5. Сохраните и опубликуйте изменения. Откройте сайт, вставьте пароль и нажмите **Войти**.

Старые `OWNER_EMAIL`, `CF_ACCESS_TEAM_DOMAIN`, `CF_ACCESS_AUD` больше не используются.
Если на домене уже включено отдельное приложение Cloudflare Access, отключите его
для домена сайта, чтобы оно не показывало прежнюю страницу входа. Защита самого
Tunnel через service token остаётся совместимой и необязательной.

Личный файл с паролем выдаётся отдельно от исходников и сборки. Не загружайте его
в GitHub или в статические файлы сайта. Сохраните пароль в менеджере паролей.
В опубликованном коде нет пароля по умолчанию.

Для самостоятельной генерации нового пароля:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Пересобрать единый Worker-файл из исходников: `npm ci` → `npm run build:worker`.
Результат — `.standalone/sova-worker.js`; он содержит сайт и сервер, без реального пароля.

## Защита

- Пароль — криптографически случайный секрет из 32 байтов; это 256 бит случайности.
  Он передаётся при входе только по HTTPS и хранится как зашифрованный Cloudflare Secret.
- Сравнение выполняется через native WebCrypto HMAC verification, без сравнения
  пользовательского пароля обычным строковым оператором и без его записи в журнал.
- При входе выдаётся отдельный случайный токен сессии на 8 часов. Cookie имеет
  `__Host-` prefix, `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/` и ограниченный срок.
- В SQLite бота хранятся только SHA-256 отпечатки случайных токенов и версии секрета.
  Сам пароль и исходный cookie-токен в эту базу не записываются.
- Каждый запрос проверяет сессию через защищённый API бота. Выход удаляет запись
  сессии, поэтому повтор старой cookie не восстанавливает вход.
- Смена `OWNER_PASSWORD` отменяет все старые сессии при следующей проверке.
- Лимит — 10 попыток за 15 минут на IP. Счётчик хранится в SQLite бота и общий для
  всех экземпляров Worker; перезапуск Worker его не сбрасывает. IP передаётся в виде
  отпечатка с секретом; исходный адрес в этой таблице не хранится.
- Запросы входа, выхода и изменения настроек проверяют Origin и специальный
  заголовок. Прямой proxy к служебным auth-endpoints запрещён.
- База хранит не более 64 сессий и 10000 активных ключей лимита; старые записи очищаются.
- Для входа бот и Tunnel должны работать. При недоступном хранилище сессий доступ
  закрывается; отдельные Cloudflare KV/D1/Durable Objects настраивать не требуется.

Полный перебор равномерного 256-битного секрета практически недостижим. Это не
защищает от копирования пароля, фишинга или вредоносного ПО на устройстве владельца.
Проверка формата 43–128 символов в приложении сама по себе не измеряет случайность;
используйте именно криптографическую генерацию, а не предсказуемую фразу нужной длины.

## Если вход не работает

| Сообщение | Действие |
| --- | --- |
| Добавьте OWNER_PASSWORD | Создайте Secret, скопируйте пароль без пробелов и опубликуйте изменения |
| Запустите обновлённого бота и Tunnel | Обновите и запустите Python, проверьте BOT_API_URL и BOT_ADMIN_TOKEN |
| Неверный пароль | Вставьте всю первую строку личного файла, без добавленного перевода строки |
| Слишком много попыток | Подождите 15 минут; правильный пароль также не обходит лимит |
| Всё ещё открывается вход по почте | На домене осталось старое Cloudflare Access-приложение |
| Сессия завершена | Введите пароль снова; срок — 8 часов или до выхода/смены секрета |

Локальный разработчик может открыть демопанель без пароля; она не обращается к
управлению ботом. Обхода серверной авторизации для разработки нет.

## Проверено

42 теста Python, 19 тестов веб-части и 6 браузерных сценариев проходят. Проверены
вход/ошибка пароля/выход/истечение сессии в интерфейсе и ограничения доступа на сервере.
Дополнительно единый собранный Worker проверен с реальным локальным HTTP API и SQLite:
вход, запрос статуса через proxy, выход, отклонение старой cookie и общий лимит попыток.
Настоящие реквизиты владельца в этих тестах не использовались.
